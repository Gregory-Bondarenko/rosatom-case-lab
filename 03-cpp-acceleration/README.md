# 03. Ускорение Python: Numba, Cython, ctypes, pybind11

Ноутбук: [cpp_acceleration.ipynb](cpp_acceleration.ipynb)

Для запуска нужен `gcc`/`g++`. Файлы `mylib.c` и `nbody_ext.cpp` ноутбук создаёт и компилирует сам

## Задачи

- **1.1.** Множество Мандельброта: чистый Python, NumPy и Numba с точным совпадением результата
- **1.2.** Метод трапеций в Cython без типов, с типами и с функцией, зашитой в модуль
- **1.3.** Своя C-функция для среднего и стандартного отклонения через ctypes
- **2.1.** Задача N тел на Numba, в том числе параллельно, с проверкой по третьему закону Ньютона
- **2.2.** Та же задача как C++ расширение на pybind11

## Что получилось

Время замерено на машине автора, соотношения между вариантами важнее абсолютных цифр

| Задача | Вариант | Ускорение к Python |
|---|---|---|
| Мандельброт | Numba | 138× |
| | NumPy | 11× |
| Трапеции | Cython без типов | 0.96× |
| | Cython, функция в модуле | 104× |
| Среднее и std | C через ctypes | 150× |
| | NumPy | 99× |

- Cython без типов не ускоряет ничего: стоимость итерации в боксинге и вызове Python-функции, а не в интерпретации байткода. Промежуточный вариант с типами, но с Python-callback это подтверждает
- `data_as` в ctypes не знает о шагах массива: срез `x[::2]` без `ascontiguousarray` молча даёт std 3.50 вместо 6.08. Однопроходная формула E[x²] − E[x]² на данных со сдвигом 1e8 даёт 1.41 вместо 1.00, поэтому в C-функции два прохода
- Третий закон Ньютона выполняется до 1e-15, но сам по себе слабая проверка: версия с 1/r вместо 1/r² тоже его проходит. Поэтому все варианты дополнительно сравниваются с независимой векторной реализацией
- На N = 4000 C++ и Numba идут вровень, около 0.08 с, NumPy примерно в 10 раз медленнее из-за матрицы попарных разностей на 250 МБ
