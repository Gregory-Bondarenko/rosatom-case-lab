# 05. Тензоры: малоранговые представления (CP, Tucker, Tensor-Train)

Ноутбук: [tensors_lowrank.ipynb](tensors_lowrank.ipynb)

Нужен `tensorly`, в ноутбуке он работает на бэкенде PyTorch

## Задачи

- **1.1.** Развёртки тензора и многолинейный ранг
- **1.2.** Разложение Таккера с заниженными, точными и завышенными рангами, сравнение с CP
- **2.1.** Сжатие цветного изображения через Tucker с рангами (r, r, 3)
- **2.2.** Tensor-Train и рост числа параметров с числом мод

## Что получилось

- У случайного тензора все развёртки полноранговые, у тензора из малого ядра ранги развёрток равны рангам ядра и различаются по модам: одного числа «ранг» у тензора нет
- Tucker с точными рангами (3, 4, 2) восстанавливает тензор до 1e-15 на 116 параметрах. CP доходит до 1e-7 на ранге 4 и 120 параметрах, то есть по компактности методы здесь почти равны. Разница в устойчивости: Tucker детерминирован, а у CP на критическом ранге ошибка между инициализациями различается на три порядка
- На изображении Tucker (r, r, 3) при равном бюджете параметров точнее поканального SVD: при сжатии в 17 раз ошибка 0.046 против 0.075, потому что пространственный базис общий для всех каналов
- TT-разложение точного ранга 4 восстанавливает тензор 8⁶ до машинной точности на 576 параметрах вместо 262 144. При 20 модах полный тензор занимал бы 1.15e18 чисел против 2368 у TT
